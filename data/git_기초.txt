Git 기초: 교육용 참고 자료

이 문서는 Git의 기본 개념을 설명하는 실습용 자료입니다. 질문에 답할 때는 이 문서에 있는 내용을 근거로 사용하세요. 문서에 없는 내용은 추측하지 말고, 확인할 자료가 없다고 말하세요.

1. Git이란?
Git은 파일의 변경 이력을 기록하고 관리하는 버전 관리 도구입니다. 이전에 기록한 상태를 확인하거나, 여러 사람이 각자의 변경 사항을 합치는 데 사용할 수 있습니다. GitHub는 Git 저장소를 온라인에서 보관하고 공유하는 서비스입니다. Git과 GitHub는 같은 말이 아닙니다.

2. 저장소와 작업 파일
저장소(repository)는 Git이 변경 이력을 관리하는 프로젝트입니다. 작업 디렉터리에서는 실제 파일을 만들고 수정합니다. 파일을 수정했다고 해서 그 내용이 곧바로 커밋에 들어가지는 않습니다.

3. 스테이징과 커밋
스테이징(staging)은 다음 커밋에 포함할 변경 내용을 고르는 단계입니다. git add 명령으로 변경 내용을 스테이징합니다. 커밋(commit)은 스테이징된 내용을 하나의 기록으로 저장하는 작업입니다. git commit 명령을 사용하며, 커밋 메시지에는 무엇을 바꿨는지 간결하게 적습니다.

기본 순서:
  파일 수정 → git status로 상태 확인 → git add로 스테이징 → git commit으로 기록

주의: 파일을 스테이징한 뒤 다시 수정했다면, 나중에 수정한 내용까지 같은 커밋에 넣으려면 git add를 다시 실행해야 합니다.

4. 브랜치
브랜치(branch)는 특정 커밋을 가리키는 독립적인 작업 흐름입니다. 새 기능을 시험하거나 수정 작업을 분리할 때 사용할 수 있습니다. 브랜치에서 작업한 내용을 다른 브랜치에 합치는 작업을 병합(merge)이라고 합니다. 브랜치를 만들었다는 사실만으로 GitHub에 자동 업로드되지는 않습니다.

5. 로컬 저장소와 원격 저장소
로컬 저장소는 내 컴퓨터에서 작업하는 저장소입니다. 원격 저장소는 다른 위치에 있는 저장소이며, GitHub에 둔 저장소가 대표적인 예입니다. git push는 로컬의 커밋을 원격 저장소로 보내는 데 사용합니다. git pull은 원격 변경 내용을 가져와 현재 브랜치에 반영하는 데 사용합니다. origin은 원격 저장소에 흔히 붙이는 이름이지만, 모든 원격 저장소의 이름이 반드시 origin인 것은 아닙니다.

6. 실습 상황 예시
민지는 app.py의 질문 출력 문구를 수정했습니다. git status로 변경 파일을 확인하고 git add app.py를 실행했습니다. 이어 git commit -m "질문 출력 문구 수정"으로 변경을 기록했습니다. 이때 커밋은 민지의 로컬 저장소에 만들어집니다. GitHub에도 반영하려면 연결된 원격 저장소로 git push를 실행해야 합니다.

7. 자주 묻는 질문
Q. git add와 git commit은 같은 작업인가요?
A. 아닙니다. git add는 다음 커밋에 넣을 내용을 고르고, git commit은 고른 내용을 기록합니다.

Q. 커밋하면 GitHub에도 바로 올라가나요?
A. 아닙니다. 커밋은 먼저 로컬 저장소에 기록됩니다. GitHub의 원격 저장소에 보내려면 git push가 필요합니다.

Q. 브랜치는 왜 사용하나요?
A. 새 기능이나 수정 작업을 다른 작업 흐름과 분리해 진행할 수 있기 때문입니다.

Q. git status는 무엇을 보여주나요?
A. 현재 작업 파일과 스테이징 상태를 확인할 수 있습니다.

8. 이 문서에서 다루지 않는 내용
충돌 해결의 구체적인 명령, GitHub Actions 설정 방법, Vercel 배포 설정 방법은 이 문서에 없습니다. 해당 질문에는 이 문서만으로는 답할 수 없다고 말해야 합니다.
